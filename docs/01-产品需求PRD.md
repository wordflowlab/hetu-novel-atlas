# 小说图鉴产品需求

## 1. 背景与目标

长篇创作的困难是持续理解整部作品。人物、关系、事件、器物与地点散在多个章节，通用画布虽自由，却把建模和操作负担交给作者。小说图鉴将已有固定内容组织为可回到依据的专业投影，由Agent维护，作者通过图、表和时间线理解并提出意见。

不将实时生成UI视为成本优势的永久前提。工程价值来自可复用的数据、稳定操作、来源、历史和低成本重绘；渲染器随技术发展可替换，作品资产持续积累。

## 2. 首版范围

| 编号 | 用户需求 | 完成结果 |
| --- | --- | --- |
| NA-01 | 从整书或明确章节建立图鉴 | 带固定来源的独立图鉴对象 |
| NA-02 | 阅读人物及势力 | 名称、类型、摘要、状态与出场依据 |
| NA-03 | 关系变化 | 带方向、性质、阶段与证据的关系 |
| NA-04 | 区分故事时间与叙事顺序 | 保留未知时间的事件时间线 |
| NA-05 | 理解地点与路径 | 地点列表与明确标记的示意投影 |
| NA-06 | 查看成长、情感与器物归属 | 属性变化和有据事件，不强制题材模板 |
| NA-07 | 从正式设定创建投影 | 固定blueprint来源，正式与推测可辨 |
| NA-08 | 迭代已有图鉴 | CAS增量更新、版本比较、原键恢复 |
| NA-09 | 可离线阅读交付 | 自包含HTML、JSON和Markdown报告 |
| NA-10 | Codex完成全部维护 | 动态能力、同包Skill、稳定CLI/MCP与GUI同状态 |

## 3. 边界

图鉴不拥有第二份正文或正式设定。抽取结果为候选，只有宿主决定能改变正式设定；关系图的布局不是地理，叙事顺序不是故事时间。默认离线导出只包含专业摘要、来源引用及所选引文，不含整章原文。

首版必须覆盖空对象、跨作品拒绝、失效来源、恶意文本、循环关系、未知位置、未知时间、超过预算、冲突、响应丢失、停用和卸载保留数据；Windows另取真实平台证据。
